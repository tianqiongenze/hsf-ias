## 1. 存储总体架构

### 1.1 选型与集群事实（直接采用，不重新勘察）

| 项 | 事实/选型 | 来源 |
|---|---|---|
| 数据库 | TiDB（`tidb.infra.svc.cluster.local:4000`，NodePort 30210；**不存在 tidb-read 主机名**） | `CONVENTIONS.md` §0 |
| 库规划 | 三库：`hsf_md`（主数据）/`hsf_biz`（业务）/`hsf_ts`（时序） | `hsf/docs/00` C2 |
| 字符集 | `utf8mb4`（建库显式指定） | 中文姓名/名称必查必存 |
| 副本容灾 | TiKV 3 副本，节点级故障数据不丢；单可用区，一期不承诺异地容灾 | `hsf/docs/01` NFR-11 / A6 |
| GIS | GeoJSON 存 `hsf_md.land_parcel.geo_json`（不引 PostGIS/GeoServer，ADR） | `hsf/docs/00` §7 |
| 时序 | `hsf_ts.sensor_reading`（不引 TimescaleDB，ADR；批量 1000 条/批写入） | `CONVENTIONS.md` §2.13 |
| 消息队列 | 无（sim 直接批量写 TiDB；Pulsar 二期接真实设备时再评估） | `hsf/docs/00` §4.2 |

### 1.2 三库职责与数据量估算

| 库 | 职责 | 表清单 | 一期量级（种子/演示） | 3 年量级 | 写路径 |
|---|---|---|---|---|---|
| `hsf_md` | 主数据：慢变、被全域引用、统一编码 | org、party、account、land_parcel、facility | org 9 / party 15 / 地块 8 / 设施 ~12 | 地块 ≤1 万、设施 ≤5 千、组织 ≤1 千 | 各子图写池（hsf_app） |
| `hsf_biz` | 业务：状态机实体、流水、审计 | farm_project、project_parcel、project_transition、facility_workorder、workorder_transition、alert_rule、alert_record、sensor、audit_log、domain_event | 项目 ~5 / 设施工单 ~10 / 告警 ~20 / sensor 48 | 项目 ≤1 千、工单 ≤1 万/年、告警 ≤5 万/年、审计 ≤10 万/年 | project/facility 子图 + sim 写池 |
| `hsf_ts` | 时序：只插入、不更新 | sensor_reading（预留 `sensor_reading_1h` 降采样归档表） | 48 台×5min tick ≈ **1.4 万条/日**（NFR-07），180 天在线 ≈ 259 万条 | 5min 原始 180 天滚动 + 1h 归档 3 年 ≈ 210 万条 | 仅 sim 写池（`execute_many` 1000/批） |

> 说明：`sensor`（设备台账）落 hsf_biz——它是 sim 域的注册表且带 `last_value/last_recorded_at` 运行时冗余列（tick 每次更新），不是慢变主数据；编码规约与主数据同风格（A-04-2）。

### 1.3 表命名与通用约定

| 约定 | 内容 | 依据 |
|---|---|---|
| 表名 | 单数、下划线（`land_parcel`）；DDL 中写全限定名（`hsf_md.org`） | DV-IAS 实践 |
| 主键 | 一律显式自增主键 `id BIGINT AUTO_INCREMENT`（时序表用 `AUTO_RANDOM`，见 §5） | `CONVENTIONS.md` §2.10"自增主键" |
| 时间列 | `created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`；`updated_at DATETIME NULL`（应用层写 NOW()，不用 ON UPDATE） | `CONVENTIONS.md` §2.10；DV-IAS 实践 |
| 唯一键 | 业务幂等键一律命名 `uk_*` | `CONVENTIONS.md` §2.10 |
| 二级索引 | 命名 `idx_*`，按"等值列在前、范围/时间列在后"排列 | TiDB 索引最佳实践 |
| 保留字 | 不用 SQL 保留字作列名（`order/desc/group/condition` 等已规避，如排序字段不出现） | `CONVENTIONS.md` §2.2 |
| 编码列宽 | CHAR(20)（L/P/F/S 编码实长 11 位，预留到 20，宁可宽不可窄）；组织码 CHAR(16)（行政区划 6/9/11 位 + 主体码实长 12 位，预留到 16——评审 R6：按 §2.3"宁可宽不可窄"，规避 DV-IAS org.code 过短坑#4 重演）；手机摘要 CHAR(64) | `CONVENTIONS.md` §2.3 |

## 2. 统一编码规则（一期核心，FR-101）

### 2.1 编码总表

| 对象 | 规则 | 长度 | 列/表 | 正则校验 | 示例（种子） |
|---|---|---|---|---|---|
| 地块 | `L` + 6 位行政区划（县码）+ 4 位县内序号 | 11 | `hsf_md.land_parcel.code` CHAR(20) | `^L\d{10}$` | L5306000001 ~ L5306000008 |
| 项目 | `P` + 6 位行政区划 + 4 位县内序号 | 11 | `hsf_biz.farm_project.code` CHAR(20) | `^P\d{10}$` | P5306000001 |
| 设施 | `F` + 6 位行政区划 + 4 位县内序号 | 11 | `hsf_md.facility.code` CHAR(20) | `^F\d{10}$` | F5306000001 ~ F5306000012 |
| 传感器 | `S` + 6 位行政区划 + 4 位县内序号 | 11 | `hsf_biz.sensor.sensor_code` CHAR(20) | `^S\d{10}$` | S5306000001 ~ S5306000048 |
| 工单流水号 | `WO` + yyyyMMdd + 6 位当日序号 | 16 | `hsf_biz.facility_workorder.sn` VARCHAR(32) | `^WO\d{14}$` | WO20261107000001 |
| 组织编码 | 行政区划节点：GB/T 2260（县 6 位/乡镇 9 位/村 11 位）；主体节点：县码 + 类型码（90=管护主体，91=合作社）+ 4 位序号 | 6/9/11/12 | `hsf_md.org.code` CHAR(16)（实长 ≤12，列宽预留——评审 R6） | 行政区划 `^\d{6}(\d{3}(\d{2})?)?$`；主体 `^530600(90|91)\d{4}$` | 530600 / 530600101 / 53060010101 / 530600900001 |

> 三类业务码统一校验正则：`^[LPF]\d{10}$`（FR-101 验收口径）；传感器并入后为 `^[SLPF]\d{10}$`。行政区划固定取**县级** 6 位码（530600 绿野县），村归属由 `village_code` 列表达，不嵌入业务码——编码全局唯一且与村解耦，村划调整不引起编码迁移。

### 2.2 生成与幂等（可落地实现）

| 项 | 规则 |
|---|---|
| 取号方式 | 写池事务外取号：`SELECT IFNULL(MAX(CAST(RIGHT(code,4) AS UNSIGNED)),0)+1 FROM <表> WHERE code LIKE 'L530600%'`（前缀走 `uk_*` 索引扫描），拼码后 INSERT，命中 `uk_*` 冲突则**重试 ≤3 次**（并发极低的县级场景足够；不引入显式事务/序列表） |
| 不可变 | 编码生成后禁改（应用层无 update code 路径；代码评审 + static_gate 门禁） |
| 序号不复用 | 地块/设施转 `RETIRED` 不回收序号 |
| 工单流水号 | Redis `INCR hsf:seq:workorder`（统一前缀 `hsf:`，评审 R21⑧；同 §8.2 键 11），Redis 不可用降级为时间戳片段（DV-IAS 已验证模式：`dv-ias/services/governance/app/repo.py:38-42`） |
| 唯一兜底 | `uk_parcel_code / uk_proj_code / uk_fac_code / uk_sensor_code / uk_wo_sn` 数据库侧强约束，重复插入报错 → `CODE_DUPLICATED`（05 号错误码） |

### 2.3 种子编码基线（验收对照）

| 对象 | 数量 | 编码区间 | 归属 | 附加约定 |
|---|---|---|---|---|
| 地块 | 8 | L5306000001~08 | 4 村各 2 块 | GeoJSON 矩形围绕 102.75E,25.05N（`hsf/docs/01` §4 种子基线） |
| 设施 | 12 | F5306000001~12 | 机井 4 / 泵站 2 / 渠道 3 / 道路 3 | 分属 4 村，部分关联地块 `parcel_code` |
| 传感器 | 48 | S5306000001~48 | 6 类×2 台×4 村 | metric 见 §4.7 |
| 组织 | 9 | 见 §9.1 | 县 1+乡 2+村 4+管护主体 1+合作社 1 | FR-701 组织树 ≥9 节点 |

```sql
-- ═══════════ 3.0 建库与双账号（部署工程师执行，CONVENTIONS §3.2；临时 pod 方式）═══════════

-- 写账号（rw）
CREATE USER 'hsf_app'@'%' IDENTIFIED BY '<gen-1>';
GRANT ALL PRIVILEGES ON hsf_md.*  TO 'hsf_app'@'%';
GRANT ALL PRIVILEGES ON hsf_biz.* TO 'hsf_app'@'%';
GRANT ALL PRIVILEGES ON hsf_ts.*  TO 'hsf_app'@'%';
-- 读账号（ro）
CREATE USER 'hsf_ro'@'%' IDENTIFIED BY '<gen-2>';
GRANT SELECT ON hsf_md.*  TO 'hsf_ro'@'%';

GRANT SELECT ON hsf_ts.*  TO 'hsf_ro'@'%';
FLUSH PRIVILEGES;
-- 密码写入 K8s Secret hsf-secrets（键名见 §7.3）
```

## 5. hsf_ts 时序 DDL

### 5.1 hsf_ts.sensor_reading（列结构承 `CONVENTIONS.md` §2.13；主键形态为对 §2.13 的显式偏离——已声明）

```sql
CREATE TABLE IF NOT EXISTS hsf_ts.sensor_reading(
  id          BIGINT        NOT NULL AUTO_RANDOM(5)
    COMMENT '显式主键改用 AUTO_RANDOM 打散写入热点（NFR-04 ≥1万条/s）；故不适用 SHARD_ROW_ID_BITS（该选项仅限无显式主键表，CONVENTIONS §2.10）',
  sensor_code CHAR(20)      NOT NULL,
  metric      VARCHAR(16)   NOT NULL,
  value       DECIMAL(10,3) NOT NULL COMMENT '观测值（value 非 SQL 保留字，可直接使用；CONVENTIONS §2.2 已复核）',
  recorded_at DATETIME(3)   NOT NULL COMMENT '毫秒精度观测时间',
  PRIMARY KEY (id),
  KEY idx_code_time (sensor_code, recorded_at)
) PRE_SPLIT_REGIONS=4
  COMMENT='传感器时序（只插入；批量 INSERT 1000 条/批，FR-502/NFR-04）';
```

- **写入契约**：sim `execute_many` 批量 1000 条/批、≥10 批/s 持续 ≥60s 达 1 万条/s（NFR-04 验证口径）。
- **读路径**：`SELECT … WHERE sensor_code=%s ORDER BY recorded_at DESC LIMIT n`（`idx_code_time` 覆盖）；`/sim/latest` 快路径直读 `hsf_biz.sensor.last_*`（免时序反查）。
- **value 列名复查**：`VALUE` 非 MySQL/TiDB 保留字（DV-IAS `telemetry` 同类列已验证）；仍将表内注释与 ORM 映射固定为 `value`，static_gate 监控该列不被重命名。
- **对 `CONVENTIONS.md` §2.13 的显式偏离声明（评审 R4 决议）**：§2.13 列清单中 `id BIGINT` 未指定主键形态，按 §2.10"预热分裂仅用于无显式主键大表"推演曾得出"无显式主键 + SHARD_ROW_ID_BITS=4 PRE_SPLIT_REGIONS=8"方案；本文冻结改采 **`id BIGINT AUTO_RANDOM(5) PRIMARY KEY + PRE_SPLIT_REGIONS=4`**，理由：① 满足 §2.10"自增主键"建表自检项（全部表显式主键，见 §6 TiDB 专项）；② AUTO_RANDOM 打散自增写热点，支撑 NFR-04 ≥1 万条/s，效果等价于 SHARD_ROW_ID_BITS 且保留显式主键；③ §2.13 列清单本身未冻结主键形态，偏离仅涉及主键实现而非列结构。**03 号 §5.5 已同步本结构**；`SHARD_ROW_ID_BITS=4 PRE_SPLIT_REGIONS=8` 规约继续适用于未来新增的无显式主键大表。

### 5.2 归档与生命周期（NFR-07：时序在线 ≥180 天，业务 ≥3 年）

| 对象 | 在线期 | 归档方式 | 执行者 |
|---|---|---|---|
| `sensor_reading` | 180 天原始值 | 到期分批删除：`DELETE FROM hsf_ts.sensor_reading WHERE recorded_at < <cutoff> LIMIT 5000`（低峰循环直至影响行数=0）；归档侧先按小时聚合写入下表 | 二期定时任务（CronJob）；一期数据量 259 万条内可全在线，仅冻结策略 |

## 7. 读写分离（双账号 hsf_app / hsf_ro）

### 7.1 账号与授权

| 账号 | 权限 | 连接池（hsf_common/db.py 移植） | 环境变量 | 用途 |
|---|---|---|---|---|
| `hsf_app` | `ALL` on 三库 | `write_pool` | `DB_USER` / `DB_PASS` | 全部写事务、写后即读、事务内读 |
| `hsf_ro` | `SELECT` on 三库 | `read_pool` | `DB_USER_RO` / `DB_PASS_RO` | 无事务读、列表、详情、聚合统计 |

### 7.2 路由规则（代码层强制，`hsf_common.db` 统一封装）

| 访问模式 | 池/账号 | 例 |
|---|---|---|
| GraphQL Query（无事务读） | `read_pool`（hsf_ro） | `landParcels` / `facilities` / `workorders` / alerts 查询 |
| GraphQL Mutation（写） | `write_pool`（hsf_app） | `registerParcel` / `createProject` / 工单流转 |
| 写后即读（同请求强一致） | `write_pool` 同连接 | 流转后返回最新实体（避免任何可见性歧义） |
| 取号读（MAX 序号） | `write_pool` | 统一编码生成（§2.2） |
| sim 批量时序写 | `write_pool.execute_many`（1000/批） | `/sim/tick` |
| 聚合统计 | `read_pool` | `/sim/alerts/statistics`、村排行 |

### 7.3 连接参数与凭据分发

| 项 | 值 | 依据 |
|---|---|---|
| 连接串 | 两池 host 相同：`tidb.infra.svc.cluster.local:4000`（**集群不存在 tidb-read 主机名**） | `CONVENTIONS.md` §0/§2.9 |
| 参数 | `charset=utf8mb4, autocommit=True, connect_timeout=3, read_timeout=5, write_timeout=5`；每工作线程 1 连接复用（ping reconnect） | DV-IAS `db.py` 已验证 |
| 延迟模型 | TiDB 多副本 raft 读，**无 MySQL 式主从复制延迟**，读池不过期分支 | DV-IAS `docs/05` §1.3 |
| 凭据分发 | K8s Secret `hsf-secrets`：`DB_USER`、`DB_PASS`、`DB_USER_RO`、`DB_PASS_RO`、`JWT_SECRET`、`REDIS_PASS`；部署时 `kubectl create secret generic hsf-secrets -n hsf-prod --from-literal=...` | `CONVENTIONS.md` §1/§3.2 |
| 权限兜底验证 | `hsf_ro` 执行 INSERT 必须报 `ERROR 1142 (INSERT command denied)`（§11 验收） | 本文档新增验收项 |
| 演进 | 一期两池同实例（账号级隔离）；二期可用 label patch 将读池固定到独立 tidb-server 实例，**应用不改代码** | DV-IAS `db.py` 头注同方案 |

## 8. 多级缓存体系

### 8.1 层级（一期落地口径）

```
L1 进程内 TTL 缓存（hsf_common.cache.L1Cache，≤10000 条，线程安全）
L2 Redis 集群（hsf-redis 3 节点，infra 命名空间，独立于一切其它租户）
L3 TiDB 读池（hsf_ro）——回源，带 singleflight 防击穿
（DV-IAS 的 L0 CDN / Nginx micro_cache 一期不建设：局域网 NodePort 直连、前端禁 CDN、
 网关不做响应缓存防 mutation 副作用——差异声明见 §10）
```

实现为 `hsf_common/cache.py`（自 `dv-ias/services/common/szxc_common/cache.py` 移植改名）：`cached(key, ttl, loader, l1_ttl)` cache-aside + 单飞 + 抖动 + 空值缓存；`invalidate/invalidate_prefix` 失效；`counter` 计数。Redis 客户端 `redis.cluster.RedisCluster`，启动节点 `hsf-redis-0.hsf-redis-h.infra.svc.cluster.local:6379`，`socket_timeout=2`，**Redis 故障降级直查 DB 不阻塞业务**（P8 原则，已验证）。

### 8.3 三大重点场景设计

| 场景 | 设计要点 |
|---|---|
| **org 树** | 读极多写极少（FR-701 每次登录/鉴权联查）。键带版本号 `v{n}`：变更时 `n+1` 新键写、旧键靠 TTL 淘汰，规避"删旧键-多副本回填旧值"竞态。L1 60s 保证同副本内高频命中；树序列化后 ~KB 级。 |
| **一张图要素** | `landGeojson(villageCode)` 是 browse 场景最重查询（p95 ≤500ms 的主保对象）。村级 FeatureCollection 一次构建全村缓存（键 2）；NFR-02 压测路径命中 L1/L2 后不触 DB。大键防护：单村要素上限 500 块（超出分片返回并提示，一期 8 块远低于限）；响应层 gzip。 |
| **排行榜/统计类** | 一期两类（键 7/9）。模式：**cache-aside + 写路径失效**（不引入定时任务）；统计 SQL 走读池 `GROUP BY`，命中 `idx_state/idx_village_time`。ZSET 键 8 为二期形态预留（真实 IoT 高频告警时改为定时 ZADD 重建 + `ZREVRANGE` 读）。 |

### 8.4 一致性与三防（沿用 DV-IAS 已验证机制）

| 机制 | 实现 | 参数 |
|---|---|---|
| 失效顺序 | 先 DB 提交 → 后删缓存（事件驱动不引入，一期无 MQ；写路径代码内显式 `invalidate`）→ TTL 兜底 | 最终一致窗口 ≤ L1 TTL（60~120s） |
| 防击穿 | 进程内 per-key singleflight 锁 + double-check | 锁等待无超时（同进程内安全） |
| 防雪崩 | TTL 抖动 | `±20%`（`ttl*(0.8+rand*0.4)`） |
| 防穿透 | 空值缓存 L2 60s；loader 返回空集/None 不进 L1 | 键 12 |
| 跨副本 L1 脏窗口 | L1 TTL ≤ L2 TTL/3；**状态敏感读**（流转后的详情）由 mutation 返回值直读写池规避 | ≤120s |
| Redis 故障 | 全部缓存操作 try/except 降级直查 DB | 不阻塞业务 |

## 10. 与 DV-IAS docs/05 的差异声明

| DV-IAS docs/05 设计 | HSF 一期处置 | 理由 |
|---|---|---|
| 四层缓存（CDN/Nginx micro_cache/Router APQ/Caffeine+Redis） | 两级（进程内 L1 + Redis L2）+ 读池 | 局域网 NodePort 直连无 CDN 层；网关为 Apollo Gateway（Node）不做响应缓存；无状态服务缓存进 hsf_common，层级更少故障面更小 |
| TiFlash 分析池 / dws 库 | 不建（统计走读池 GROUP BY） | 一期统计量级小（48 台传感器/万级行）；避免增加 TiFlash 组件运维 |
| 多个业务域分表分区（按月 PARTITION） | 不分区（sensor_reading 用 AUTO_RANDOM+PRE_SPLIT 替代） | 单表年行数 <600 万，分区收益不抵复杂度（NFR-07 估算） |
| `szxc_sensitive` 独立敏感库 | 不建；敏感字段（手机号/联系方式）SM4-GCM 列级加密在 hsf_md/hsf_biz 内 | 一期敏感字段仅两类，列级加密+脱敏达标（NFR-06），独立库三期评估 |
| 事件驱动缓存失效（Outbox+Pulsar） | 写路径显式失效 + TTL 兜底 | 一期无 MQ（00 §4.2）；跨副本脏窗口 ≤120s 可接受 |
