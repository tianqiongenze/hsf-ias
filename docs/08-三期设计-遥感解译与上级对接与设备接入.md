## 1. 范围与不做（诚实边界）

| 项 | 三期做 | 三期不做（显式） |
|---|---|---|
| 遥感解译 | 影像元数据登记→NDVI CPU 解译→按地块聚合长势分级→非农化预警规则→一张图/管理端呈现 | 深度学习作物分类模型（无 GPU，V-1）；真实卫星影像源接入（内网无外网，V-2 样本栅格走通全链路，输入适配器单文件可替换）；PostGIS/OpenLayers（ADR-001 再评：单村地块 <1 万、仍无空间分析诉求、无底图服务源——继续 SVG+JSON 路线，触发器不满足） |

| 设备接入框架 | 设备注册 API（管理员）+ 接入凭证下发 + mosquitto ACL 细化（每设备仅 own topic）+ 接入说明文档 | 真实硬件到货联调、NB-IoT/LoRa 网关适配（协议层 MQTT 已真实，硬件层待设备）；**broker 侧设备凭证追加与端到端设备可连**（运行时后补项，规格冻结于 §4——后补前已注册设备无法通过 broker 认证，见 §4"broker 凭证现状与后补规格"） |

## 2. 遥感解译 rs 服务（:8098，NodePort 31214）

### 2.1 数据模型（TiDB hsf_biz 增表，D-08-1：存量零变更只新增）

```sql
CREATE TABLE IF NOT EXISTS hsf_biz.rs_scene(
  id           BIGINT NOT NULL AUTO_INCREMENT,
  scene_code   CHAR(32) NOT NULL COMMENT '影像景编码（调用方生成，幂等键）',
  source       VARCHAR(32) NOT NULL DEFAULT 'SAMPLE' COMMENT 'SAMPLE=合成样本/SENTINEL=真实（预留）',
  acquired_at  DATETIME NOT NULL COMMENT '成像时刻（naive 本地，A-04-3 口径）',
  bands        JSON NOT NULL COMMENT '波段清单 ["red","nir"]（样本栅格内联 JSON 矩阵）',
  width        INT NOT NULL, height INT NOT NULL,
  cell_size_m  DECIMAL(8,2) NOT NULL DEFAULT 10.0 COMMENT '像元分辨率（米）',
  state        VARCHAR(16) NOT NULL DEFAULT 'REGISTERED' COMMENT 'REGISTERED/PROCESSED/FAILED',
  created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id), UNIQUE KEY uk_scene (scene_code)
) COMMENT='遥感影像登记（D-08-1 新增，存量零变更）';

CREATE TABLE IF NOT EXISTS hsf_biz.rs_vigor(
  id           BIGINT NOT NULL AUTO_INCREMENT,
  scene_code   CHAR(32) NOT NULL,
  parcel_code  CHAR(20) NOT NULL COMMENT '跨库逻辑引用 land_parcel（D-04-3）',
  ndvi_mean    DECIMAL(6,4) NOT NULL, ndvi_min DECIMAL(6,4) NOT NULL, ndvi_max DECIMAL(6,4) NOT NULL,
  vigor_level  VARCHAR(16) NOT NULL COMMENT '旺长/正常/偏弱/长势差（四级，docs/08 §2.3 样本期标定阈值）',
  pixel_count  INT NOT NULL,
  created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id), UNIQUE KEY uk_vigor (scene_code, parcel_code),
  KEY idx_vigor_scene (scene_code)
) COMMENT='按地块 NDVI 长势（解译结果）';
```

### 2.2 解译管道（numpy 纯 CPU，V-1）

```
REGISTERED → process(scene_code)：
  ① 读 bands JSON → numpy float32 矩阵（red/nir，width×height）
  ② NDVI = (nir - red) / (nir + red + 1e-6)          # 防零除
  ③ 地块掩膜：种子地块 GeoJSON（land 子图 landGeojson）→ 经纬度→像元索引线性映射
     （docs/02 ADR-001 口径：WGS84 线性映射，无投影转换）
  ④ 按地块聚合 ndvi_mean/min/max + pixel_count
  ⑤ 分级（§2.3 样本期标定阈值）落 rs_vigor；scene.state=PROCESSED
失败 → state=FAILED + domain_event 留痕（outbox 模式，ADR-HSF-004 沿用）
```

### 2.3 长势分级与非农化预警（样本期标定阈值，非业务冻结契约）

**定级声明**：下表四级分界与非农化预警参数均为**样本期临时工程标定**（V-2 合成样本栅格的 NDVI
分布按此构造，用于打通"解译→分级→预警"链路）——无文献/行业标准/本地作物物候定标依据，
**不构成业务冻结契约**；NDVI 绝对值随传感器、大气校正、作物类型与生育期漂移，单一绝对区间
跨作物跨季节不可辩护，真实影像下必须重标定（复评机制见下）。

| vigor_level | NDVI 均值区间（标定值） | 业务含义 |
|---|---|---|
| 旺长 | ≥0.60 | 长势旺盛（关注徒长/倒伏风险提示） |
| 正常 | [0.40, 0.60) | 正常生长 |
| 偏弱 | [0.20, 0.40) | 水肥不足/灾害前兆（联动灌溉建议复核） |
| 长势差 | <0.20 | 严重异常（触发核查） |

**非农化预警**（标定参数）：同一 parcel 相邻两景 NDVI 均值降幅 >0.15 且后景 <0.30 → 生成 `alert_record`
（rule_code=RULE_NDVIFALL，复用二期告警/通知管道——iot 通知服务端写入口径不变，rs 直接写
hsf_biz.alert_record+notify，与 D-07-1"规则引擎唯一方"并行不冲突：NDVI 预警是独立数据源的新规则）。

**复评机制（真实影像重标定）**：真实影像源接入时（三期不做，§1）或任一真实场景首轮解译前**必须重标定**——
取同村同作物多期真实 NDVI 样本分布分位数（如 P25/P50/P75）对齐四级边界，回测非农化预警误报/漏报后
经评审更新生效；阈值唯一实现点 `rs/app/ndvi.py`（`VIGOR_LEVELS`/`FALL_DROP`/`FALL_CEIL`），改代码不改表结构；
标定记录（数据源、样本量、分位数、生效日期）写入 `docs/22` 环境阻塞与变更记录。

## 3. 上级平台对接 uplink 服务（:8099，ClusterIP）

### 3.1 上报 payload 契约（D-08-2，统一编码映射）

```json
{
  "reportBatch": "B20261108001",
  "countyCode": "530600",
  "items": [
    {"type": "PROJECT", "code": "P5306000001", "name": "...", "state": "ARCHIVED",
     "villages": ["53060010101"], "amountWan": 1200.0, "timeline": {...}},
    {"type": "PARCEL", "code": "L5306000001", "areaMu": 12.5, "holderName": "...",
     "villageCode": "53060010101", "geoWktHint": "POLYGON(...前3点...)"},
    {"type": "FACILITY", "code": "F5306000001", "kind": "渠", "parcelCode": "L5306000001", "state": "ACTIVE"},
    {"type": "SENSOR", "code": "S5306000001", "metric": "soil_moisture", "villageCode": "...",
     "parcelCode": "L5306000001"}
  ]
}
```
映射规则：`L/P/F/S` 统一编码前缀→上报 type（PARCEL/PROJECT/FACILITY/SENSOR）；SENSOR 项带
`parcelCode`（设备注册契约 §4 登记的地块关联，取 hsf_biz.sensor.parcel_code——上级平台按地块聚合传感器，
与 FACILITY 项同口径；可为空=未挂地块）；state 按 ARCHIVED 等枚举直传；面积/金额以登记值为准
（ADR-001"面积重算以登记值为准"口径延续）。

### 3.2 状态机与幂等（D-08-3）

```sql
CREATE TABLE IF NOT EXISTS hsf_biz.uplink_task(
  id BIGINT NOT NULL AUTO_INCREMENT,
  batch_code CHAR(32) NOT NULL COMMENT '批次编码（幂等键）',
  payload JSON NOT NULL, item_count INT NOT NULL,
  state VARCHAR(16) NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING/SENT/ACKED/REJECTED',
  receipt JSON NULL COMMENT '回执（stub 或真实平台）',
  sent_at DATETIME NULL, created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id), UNIQUE KEY uk_batch (batch_code)
) COMMENT='上级平台上报任务（D-08-3 新增）';
```

| 方法 | 说明 |
|---|---|
| POST /tasks | 创建上报任务（幂等：batch_code 重复→返回已有任务不重复创建）；payload 由 uplink 从 hsf_md/hsf_biz 自主组装（countyCode 参数） |
| POST /tasks/{batch}/send | transport.send(payload)→stub 校验完整性→回执 `{accepted:true, receipt:{taskId, checksum}}`→state=SENT→ACKED；校验失败→REJECTED+原因 |
| GET /tasks?state=&page= | 分页查询 |
| GET /tasks/{batch}/payload | 导出完整 payload JSON（归档口径，docs/05 §8.1"导出通道"落地） |

`transport.py` 隔离层（V-3）：`class Transport: def send(self, payload: dict) -> dict`——stub 实现
校验必填字段+checksum；真实平台仅替换此文件。

## 4. 设备接入框架（iot 3.0 增量）

- `POST /devices/register`（admin）：`{deviceCode, metric, villageCode, parcelCode}` → 新设备入库
  hsf_md.sensor（state=ACTIVE）+ 生成接入凭证 `mqttPassword=SM3(deviceCode+盐)[0:16]`（国密口径：
  docs/02 国密套件/NFR-06，实现 `hsf_common.crypto.sm3`）→
  返回凭证一次（不落明文，`mqtt_passwd_hint` 存 sha256 前 8 位供核对）；
- mosquitto ACL 细化：`hsf-prod` ConfigMap `acl` 含每设备 pattern 行
  `pattern readwrite hsf/sensor/%u/#`（%u=设备 username=deviceCode）——语义为**每设备仅能读写自己的
  topic**（`30-mqtt.yaml` 已冻结该行）；注意 pattern 行本身不产生认证：生效前提是 broker
  `password_file` 中存在对应设备账号（见下条后补规格）；
- **broker 凭证现状与后补规格（诚实边界，2026-11-13 评审修订）**：当前 passwd-init 以
  `mosquitto_passwd -b -c` 幂等覆盖重建单账号 hsf（`30-mqtt.yaml` initContainer），设备凭证仅落
  TiDB hsf_biz.device_cred（SM3 摘要+hint）——`allow_anonymous false` 下**已注册设备尚无法通过
  broker 认证，端到端设备可连未闭环**（真实硬件未到货，§1 显式不做）。后补规格（真实硬件到货联调前完成，
  上线前动作清单见 §6）：
  ① `scripts/dep-device.sh <deviceCode> <mqttPassword>`：以注册响应一次性下发的明文凭证执行
  `mosquitto_passwd -b /mosquitto/data/passwd <deviceCode> <pass>` 追加（**禁用 `-c`**——`-c` 整文件
  覆盖重建会抹掉既有设备条目）→ `kubectl -n hsf-prod rollout restart statefulset/hsf-mosquitto` 生效；
  凭证明文不落库（device_cred 只存摘要），故只能凭注册响应同步执行，事后无法从库还原；
  ② 配套 passwd-init 改造：passwd 文件已存在且含 hsf 账号时**跳过 `-c` 重建**（仅文件缺失时按
  Secret 初始化）——否则 broker pod 每次重启都会抹掉追加的设备条目；
  ③ 后补完成后实机验证：用注册凭证连接 own topic 收发成功、他人 topic 拒绝（mosquitto_pub/sub）。
- 注册后 iot registry ≤60s 自动刷新（二期 REGISTRY_REFRESH 机制复用）；
- `docs/08` 附接入说明（连接参数、QoS、payload 契约——引用 docs/07 §2.2 冻结格式）。

## 7. 验收增量（X 配套）

- **E2E ≥25**（新增 ≥6）：影像登记→解译→长势查询；非农化预警生成；上报任务→回执→状态闭环；
  设备注册→凭证下发（**API 口径：200+凭证字段+幂等 409，不含 broker 连通**——端到端设备可连为
  §4 运行时后补项，实机验证入 §6 上线前核验）；admin 遥感页签渲染；同源反代 /rs/ 200。
- **k6**：browse/report 判据同二期；iot-write 复跑（check 目标 ≥98%——W-1 效果观测，不进 thresholds）。
- **门禁**：static_gate P3 项（rs 无 torch/tf、uplink 必含 transport.py、E2E≥25、3.0 tag 一致、新服务探针）。
- **单元测试**：rs（NDVI 计算与分级）、uplink（payload 组装与状态机）、iot（注册凭证）——不依赖外部服务。
