## 1. 选型总原则与继承声明

### 1.1 三条仲裁原则（与 DV-IAS docs/03 §1 对齐并裁剪）

| # | 原则 | 在 HSF 的具体含义 |
|---|---|---|
| P1 | **复用优先** | 集群已有 TiDB/Prometheus/Grafana/Registry/Redis 运行经验一律复用；不新增任何有状态中间件（一期） |
| P2 | **已验证优先于先进** | 凡 DV-IAS 在同集群生产验证过的模式（联邦网关、多级缓存、状态机、压测体系），直接移植改名，不"重新发明" |
| P3 | **局域网自足** | 前端零 CDN、零外网依赖；库文件进镜像；一切能力闭环于集群内网（`CONVENTIONS.md` §0） |

## 2. 需求对标（为什么这些选型能接住需求）

原文章"五横三纵+用户层"能力 → 本架构落点（完整映射见 `hsf/docs/00` §3，此处只列**决定技术选型**的关键项）：

| 原文章能力（层） | 对架构的硬约束 | 本文落点（章节） |
|---|---|---|
| 统一编码（数据层） | 三类编码全局唯一、不可变、跨域引用 | 编码体系进入各表 `uk_*` 唯一键 + CHAR(20) 列宽（`03` §5） |
| 时空数据库+GIS 中台+一张图（数据/平台/应用层） | 地块几何存储、按村取图、点击属性 | ADR-HSF-001（§3.1） |
| 时序库+IoT 中台（数据/平台层） | 高频写入、阈值告警 | ADR-HSF-002/003（§3.2/§3.3） |
| 项目全周期（应用层） | 7 态状态机、非法流转拒绝 | `03` §4.3 状态机转移表 |
| 设施管护（应用层） | 4 态工单、二维码、移动扫码 | `03` §4.4 |
| 统一门户/权限（平台层） | JWT、五角色 RBAC+数据范围、审计 | `03` §4.1、§5.7 权限矩阵 |
| 三体系（标准/安全/运维） | 纵向贯穿所有横层 | §4 层×域图的右侧三纵 + §8/§9 |

**容量口径承继**（`hsf/docs/01` §5 NFR、§7 假设）：读 p95≤500ms、写 p95≤800ms、时序写入≥1 万条/s、可用性 99.9%、"5 万在线"为容量设计目标（k6 200VU 实测门槛+模型外推，假设 A5）。本文所有组件选型不引入与该口径冲突的共享瓶颈。

## 3. 新增技术决策（ADR 式）

> 格式对齐 DV-IAS `docs/adr/` 惯例：背景/决策/理由/备选与不选理由/影响与限制/演进触发器。每个 ADR 都给出**可验收的验证方式**。

### ADR-HSF-001 GIS 方案：TiDB 存储 GeoJSON + 前端纯 SVG 渲染

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（一期冻结）｜ 决策日期 2026-11-07 ｜ 决策人：架构设计师（工作流） |
| 背景 | ① 原文章要求"时空数据库（地块/灌排设施/道路）+ GIS 中台（空间分析/三维/专题图）+ 一张图"；② 集群事实：**无 PostGIS、无 GeoServer**，共享多租户 2 节点；③ 局域网客户端可能无法访问外网 CDN（`CONVENTIONS.md` §0），前端严禁 CDN；④ 一期 GIS 诉求仅为**查询级**：按村返回 FeatureCollection（FR-103）、SVG 渲染与点击属性（FR-201/202）、统计角标（FR-203）——无空间分析（缓冲区/相交/测距）、无三维、无瓦片服务诉求 |
| 决策 | 1. **存储**：`hsf_md.land_parcel.geojson` 以 JSON 列存储 GeoJSON geometry（Polygon 起步），坐标 WGS84；2. **服务**：land 子图提供 `landGeojson(villageCode)` 返回合法 FeatureCollection（服务端拼装，不落文件）；3. **渲染**：web 一张图页**纯 SVG `<polygon>` 渲染**为主路径；构建期若能下载则将轻量 GIS 库（Leaflet）vendored 进镜像作增强，运行时检测 `window.L` 缺失**自动回退 SVG**，两态均可用（`CONVENTIONS.md` §2.12 原文冻结） |
| 理由（编号） | R1 集群无 PostGIS/GeoServer——引入即新增 2 个有状态服务+存储+备份+升级链路，违背 P1；R2 一期无空间函数诉求，JSON 列全量返回+前端渲染即可满足 FR-103/201/202/203 全部验收标准；R3 禁 CDN 约束下纯 SVG（浏览器原生）是唯一"零依赖必可用"方案，vendored Leaflet 仅作渐进增强；R4 数据量边界内性能充裕：种子 8 地块、单村地块数百级以内，FeatureCollection 全量返回 <1MB（一期按"单村地块 <1 万"为容量护栏，见影响与限制）；R5 降低有状态服务数，K8s 部署面（Deployment 数）与故障面同步缩小 |
| 备选与不选理由 | ① **PostGIS+GeoServer**：功能最强但集群无此栈，需新建有 StatefulSet/独立库与运维，二期随空间分析需求一并评估（触发器见下）；② **OpenLayers**：功能覆盖投影/要素交互强于 SVG 裸写，但 vendored 体积与复杂度高于 Leaflet，一期"点选+渲染"场景不必要——**列为二期 GIS 增强评估项**（本 ADR 与任务指令"SVG/OpenLayers"的差异：以 `CONVENTIONS.md` §2.12 冻结的"SVG 主路径 + Leaflet vendored 增强"为准，OpenLayers 与 PostGIS 绑定在二期同评）；③ **Cesium（三维）**：三期数字孪生场景再看（`hsf/docs/00` §3"不承诺"）；④ **瓦片预生成服务**：无底图数据源（无外网瓦片），不成立 |
| 影响与限制（诚实声明） | ① 不支持 SQL 空间函数（`ST_*`）查询——空间过滤仅能按村/按属性，几何过滤在前端；② 无服务端空间分析能力（缓冲区/相交/面积重算以登记值为准）；③ geometry 校验为应用层格式校验（JSON 结构+环闭合抽查），非拓扑校验；④ 坐标系仅 WGS84，不含投影转换（渲染按经纬度线性映射） |
| 演进触发器 | 任一满足即启动二期评估：单村地块 >1 万；出现相交/缓冲区/沿路统计类需求；接入遥感影像（三期）；甲方要求接入国土空间一张图底图服务 |
| 验证方式 | FR-103（FeatureCollection 合法性与数量）、FR-201/202（E2E SVG 元素数≥种子地块数、点击属性面板）、FR-204（static_gate grep 零 CDN 引用） |

### ADR-HSF-002 时序方案：TiDB `hsf_ts`（不引入 TimescaleDB/TDengine）

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（一期冻结）｜ 决策日期 2026-11-07 ｜ 决策人：架构设计师（工作流） |
| 背景 | ① 原文章要求"时序库（墒情/气象实时）"；② 集群事实：无 TimescaleDB/TDengine（理由 R1 同 ADR-001）；③ 一期数据量：48 台模拟传感器×5min tick ≈ **1.4 万条/日**，年内 <600 万条（`hsf/docs/01` NFR-07）；④ 写入目标 ≥1 万条/s（NFR-04）为**压测能力口径**而非日常负载 |
| 决策 | 1. 独立库 `hsf_ts`，核心表 `sensor_reading`（列结构承 `CONVENTIONS.md` §2.13：`sensor_code CHAR(20)`、`metric VARCHAR(16)`、`value DECIMAL(10,3)`、`recorded_at DATETIME(3)`、`KEY idx_code_time(sensor_code, recorded_at)`；主键实现冻结为 `id BIGINT AUTO_RANDOM(5) PRIMARY KEY + PRE_SPLIT_REGIONS=4`——对 §2.13"无显式主键"口径的**显式偏离**，偏离声明见 04 号 §5.1，更符合 §2.10"自增主键"建表自检项）；2. 写入：sim 服务批量 INSERT **1000 条/批**（`hsf_common.db.execute_many`）；3. `SHARD_ROW_ID_BITS=4 PRE_SPLIT_REGIONS=8` 规约（§2.10）**仅适用于无显式主键大表**——`sensor_reading` 已有显式主键，不适用该选项；4. 保留策略：在线 ≥180 天，超期按 04 号文档归档脚本转储 |
| 理由（编号） | R1 集群无该组件，新增=有状态服务+运维（同 ADR-001 R1）；R2 一期日常写入 1.4 万条/日，TiDB 容量与吞吐余量两个数量级以上；R3 万条/s 峰值能力：DV-IAS 同集群已完成 1.058 亿行时序批量写入融合验证（commit e149e3c、`docs/15`），批量写模式可平移，HSF 以 NFR-04 基准压测复验；R4 `idx_code_time(sensor_code, recorded_at)` 覆盖"按设备取最新值/时间窗"两类高频查询（FR-502 `/sim/latest`、告警规则扫描）；R5 与业务库同引擎，运维技能/备份/监控一套 |
| 备选与不选理由 | ① **TimescaleDB**：PostgreSQL 系，需新建库+压缩/连续聚合特性在 2 节点共享集群的收益不成比；② **TDengine**：独立时序引擎，新增有状态服务与备份链路；③ **Pulsar+TiDB 管道**：一期无流式消费诉求，先落库再查询即可（与 ADR-HSF-004 一致）；④ 以上均登记为二期真实 IoT 接入时的评估项 |
| 影响与限制（诚实声明） | ① 无降采样/连续查询/数据压缩等时序库专有能力——降采样在查询层 GROUP BY 时间桶实现，超长窗口查询性能依赖索引与缓存；② 单表容量护栏：>5 亿行/年时必须先做归档再谈扩容（04 号文档设计归档任务）；③ 写入吞吐依赖批大小，禁止单条 INSERT 高频写（sim 实现约定） |
| 演进触发器 | 真实设备接入且峰值 >5 万点/s；需要连续聚合/降采样物化；hsf_ts 单表 >5 亿行——满足其一启动 TimescaleDB/TDengine 二期 ADR |
| 验证方式 | NFR-04 基准压测（≥1 万条/s×60s，0 失败、无死锁/锁冲突）；FR-502（tick 后 latest 单调递增）；FR-503（4 条规则边界值单测 14.9/15.1、84.9/85.1、16.9/17.1、79.9/80.1） |

### ADR-HSF-003 sim 独立 REST 服务（FastAPI，非 GraphQL 子图）

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（一期冻结，端口与形态冻结于 `CONVENTIONS.md` §1/`hsf/docs/00` §5） |
| 背景 | sim 承担三类职责：模拟数据生成与批量写入（`POST /sim/tick`）、设备清单查询、告警查询/统计（状态推进处置接口二期 P2，05 号 A-05-2）。前两类是机器调用或简单只读端点 |
| 决策 | sim 为 **FastAPI REST 服务**（端口 8095，NodePort 31211），不暴露 GraphQL、不加入联邦组合；告警数据落 `hsf_biz.alert_record`（`hsf/docs/01` FR-503 冻结口径），供 web 页面与 E2E/压测脚本直连 REST 消费；sim 开启 CORS 白名单允许 web 源跨域读取告警（web 为纯静态页、无后端代理） |
| 理由 | R1 批量写入端点用 GraphQL 反增解析开销与契约复杂度，REST+JSON 数组最直给；R2 告警消费方（web 大屏角标/移动端列表）只需 GET，REST 足够；R3 压测脚本（locust/k6）打 REST 直连 31211，绕过网关避免与业务流量互相限流干扰；R4 保持 4 个 GraphQL 子图的联邦面干净（设备/时序/告警无跨子图 `@key` 互查诉求） |
| 备选与不选理由 | ① GraphQL 子图：无跨子图实体引用需求，组合收益为零；② 并入 iam 子图：违反单一职责与部署隔离（sim 可独立重启/压测） |
| 影响与限制 | 告警查询不经网关 → 不受网关 JWT/限流保护，sim 自身必须做数据范围过滤（按 `x-user-*` 透传或查询参数村码过滤，`03` §4.5 冻结）；REST 无 SDL 契约 → 以 OpenAPI（FastAPI 自带 `/docs`）+ 05 号文档接口表冻结 |
| 验证方式 | FR-501~505 全部验收标准；压测 NFR-04 直连 31211 |

### ADR-HSF-004 一期无消息队列：领域事件=Outbox 表 + 联邦引用

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（一期冻结；与 `hsf/docs/00` §4.2"一期无 RAG/图谱/事件总线诉求"一致） |
| 背景 | DV-IAS 跨上下文协作靠 Pulsar（`docs/04 §5`：Outbox+Pulsar 至少一次投递）。HSF 一期盘点跨上下文交互后：**读侧** 6 条协作全部可用联邦 `@key` 引用解决（`03` §4.6 矩阵），**写侧**仅两条弱异步诉求（审计、事件留痕），均可同事务落库解决——不存在需要 broker 的消费者 |
| 决策 | 1. 领域事件统一**事务性写入** `hsf_biz.domain_event`（Outbox 表：id/topic/payload JSON/created_at/published_at）；2. 跨上下文**读**协作一律 GraphQL 联邦引用（编码存本方表、对象经 `_resolve_reference` 跨子图解析）；3. 审计由各子图在**同一写事务**内 INSERT `hsf_biz.audit_log`（不依赖事件消费）；4. 事件 topic 命名预留 `hsf.<ctx>.<entity>.<verb-past>`（对齐 DV-IAS `szxc.*` 规范，`docs/04 §6`），AsyncAPI 登记于 05 号文档 |
| 理由 | R1 一期事件消费者集合为空，引入 Pulsar=有 broker 无订阅者的"半套 MQ"（运维成本无收益）；R2 Outbox 表已保留事件语义与完整审计轨迹，二期上 Pulsar 时仅需增加**投递器**（轮询 published_at IS NULL → 发 Pulsar → 置位），业务代码零改动；R3 同事务落审计保证 FR-704"写操作必留痕"的强一致（消息队列做不到 at-least-once 之外的即时可见） |
| 备选与不选理由 | ① Pulsar（集群已有）：无消费者，纯成本；② 进程内事件总线：跨副本不可见，语义弱于 Outbox 表；③ 同步 REST 调用链（如 project 创建时调 land 校验）：**不选跨服务 HTTP 同步调用**，改用同 TiDB 实例跨库 SELECT 校验（见 `03` §4.6/§7——`hsf_app` 对三库均有权限，`CONVENTIONS.md` §3.2 冻结），消除分布式调用失败面 |
| 影响与限制 | 事件无实时订阅方 → "事件驱动"在退化为"事件记录"；任何需要实时联动的新需求（如告警自动生成工单）必须先立项升级投递器，不允许绕过 Outbox 私拉 HTTP |
| 演进触发器 | 二期真实 IoT 接入（设备上行→规则→多消费者）即引入 Pulsar+投递器，topic 命名已预留 |
| 验证方式 | 每个写 mutation 后 `domain_event` 新增 1 行（单测断言）；审计同事务断言（FR-704） |

## 11. 与 DV-IAS 架构的逐项差异对照（诚实声明）

| 项 | DV-IAS（docs/02/03/04） | HSF 本文 | 差异理由 |
|---|---|---|---|
| 网关 | 选型报告写 Apollo Router（Rust），**实际落地 Node Apollo Gateway** | Node Apollo Gateway（承继实际实现） | 以已验证实现为准（§1.2 诚实修正） |
| 后端语言 | Java 21 + Spring Boot 3（DGS 子图）+ Python（AI） | Python 3.13 + FastAPI + Strawberry 单语言 | `szxc/base:1.2` 免构建；一期 5 服务规模无需 JVM 栈 |
| 服务数量 | 12 领域服务+3 平台组件 | 4 子图 + 1 REST 服务 + gw + web | 一期范围裁剪（`hsf/docs/00` §6.1） |
| 事件总线 | Pulsar + Outbox | Outbox 表（ADR-HSF-004） | 一期无消费者 |
| 缓存 L1 | Caffeine（Java） | 进程内 LRU（Python `cache.py` L1Cache） | 语言随行 |
| GIS | 高德 JS API/大屏（乡村治理场景） | TiDB GeoJSON + SVG/Leaflet vendored（ADR-HSF-001） | 集群无 GIS 栈+禁 CDN |
| 时序 | TiDB 按天分区（方案 A，同款决策） | TiDB `hsf_ts`（ADR-HSF-002，独立库强化隔离） | 同款决策，库级隔离 |
| 配置中心 | Nacos（docs/03 §5.1） | K8s ConfigMap/Secret（`hsf-secrets` 等） | 一期配置面小，少一个组件 |
| 数据中台/AI | data-svc + agent-runtime + MCP | 不设（三期） | 一期无诉求（`hsf/docs/00` §4.2） |
