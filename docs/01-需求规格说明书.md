## 4. 功能需求（FR）

> 编号规则：FR-1xx 地块域、FR-2xx 一张图、FR-3xx 项目域、FR-4xx 设施域、FR-5xx 时序告警域、FR-6xx 移动端、FR-7xx 权限审计域。
> 每条"验收标准"均为可在验收环境执行的判定（种子数据基线：县 1 + 乡镇 2 + 村 4 + 管护主体 1 + 合作社 1；地块 8 个，GeoJSON 矩形围绕 102.75E,25.05N；模拟传感器 6 类×每村 2 台）。

### 4.1 FR-1xx 统一编码与地块主数据（land 子图）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-101 | **统一编码规则**：地块 `L+6位行政区划+4位序号`（11 位）、项目 `P+6位行政区划+4位序号`、设施 `F+6位行政区划+4位序号`；行政区划采用 GB/T 2260 6 位代码；编码列宽 CHAR(20) 预留（宁可宽不可窄，`CONVENTIONS.md` §2.3）；编码全局唯一、生成后不可变 | ① 三类编码正则校验（`^[LPF]\d{10}$`）通过；② 重复编码插入被唯一键 `uk_*` 拒绝；③ 种子 8 个地块编码符合规则 |
| FR-102 | **地块台账**：登记地块（编码、名称、所属村、权属人、面积亩、土壤属性、作物属性、GeoJSON 几何）；支持按村分页查询、按编码精确查询 | ① `registerParcel` 成功创建并返回编码；② `landParcels(villageCode)` 分页返回本村地块；③ `landParcel(code)` 返回全部属性字段 |
| FR-103 | **地块 GeoJSON 服务**：按村返回 GeoJSON FeatureCollection（一张图数据源），geometry 至少支持 Polygon | ① `landGeojson(villageCode)` 返回合法 FeatureCollection，features 数=本村地块数；② 种子 8 地块均在 102.75E,25.05N 附近且坐标合法 |
| FR-104 | **权属联邦引用**：地块权属人 holder 以联邦实体 `Party`(@key id) 引用（跨子图取 name 等） | `{ landParcel(code:"…"){ code holder { name } } }` 一次查询返回真实种子数据（联邦组合成功） |

### 4.2 FR-2xx 一张图展示（web + land）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-201 | **地块图层渲染**：一张图页加载后以 SVG polygon 渲染本县地块边界（纯 SVG 方案）；若本地 vendored Leaflet 可用则增强渲染，`window.L` 缺失自动回退 SVG，两态均可用 | E2E：一张图页加载后 SVG 地块元素数量 ≥ 种子地块数，HTTP 200 |
| FR-202 | **要素点击属性**：点击地块显示编码/名称/村/面积/作物/权属人 | E2E：点击任一地块元素后属性面板出现该地块编码 |
| FR-203 | **图层统计**：显示地块总数/总面积/告警数角标（数据来自 land 与 sim 聚合查询） | 统计数字与 `landParcels.total`、`landStats.totalAreaMu`（05 号 §4.1 冻结查询，FR-203 面积聚合落点——评审 R15）、`/sim/alerts/statistics` 返回值一致 |
| FR-204 | **离线可用（禁 CDN）**：静态页与库文件全部进镜像，无任何外网 CDN 引用 | static_gate grep 无 CDN 引用；局域网无外网环境三页均 HTTP 200 |

### 4.3 FR-3xx 项目全周期状态机（project 子图）

状态机（7 态，非法流转一律拒绝）：
`储备(RESERVED) → 申报(SUBMITTED) → 审批(APPROVED) → 施工(CONSTRUCTING) → 监理(SUPERVISED) → 验收(ACCEPTED) → 绩效(PERFORMED)`
（状态枚举名以 03/04 号文档 DDL/SDL 冻结为准，流转拓扑不变。）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-301 | **项目立项**：创建项目（编码 P+…、名称、年度、建设内容、关联地块[]、申报单位、监理人 supervisor→Party） | `createProject` 返回 P 编码；项目-地块多对多关联可查询（`parcels→[LandParcel]`） |
| FR-302 | **状态机流转**：仅允许沿上述拓扑推进；每次流转记录操作人与时间 | `submitProject/approveProject/startConstruction/…` 依序执行全部成功；状态逐态变化留痕 |
| FR-303 | **非法流转拒绝**：跨态或回退流转（如 储备→施工、验收→申报）返回业务错误码，不落库 | 单测：全部非法转移对被拒绝（状态机转移表全覆盖）；E2E 含一次非法流转被拒断言 |
| FR-304 | **监理关联**：项目监理人以 `supervisor→Party` 联邦引用 | `{ farmProject(code:"…"){ supervisor { name } } }` 返回真实数据 |
| FR-305 | **验收归档**：验收态后归档验收结论，进入绩效态闭环 | `acceptanceArchive` 后项目状态=绩效态，归档内容可查询 |

### 4.4 FR-4xx 设施台账与二维码巡检工单（facility 子图）

设施类型一期：**机井、泵站、渠道、道路**（对齐原文章灌排设施；可扩展）。
工单状态机（4 态）：`受理(accept) → 派单(dispatch) → 办结(resolve) → 销项(approve)`（复用 DV-IAS 事件流转模式）。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-401 | **设施台账**：登记设施（编码 F+…、类型、名称、所属地块 land_parcel_code 外联、建设年度、状态） | ① 台账 CRUD 成功；② `{ facility(code:"…"){ parcel { code } } }` 联邦返回关联地块 |
| FR-402 | **设施二维码**：为设施生成二维码，内容=移动端 URL+设施 token；扫码直达设施详情（一期交付 token+URL；**二维码图片渲染为一期可选增强、默认二期**——生成方式：前端 vendored qrcode 库或服务端 SVG，未在一期冻结，见 03 号 §4.4 口径说明，评审 R22；未实现不影响本条验收） | 二维码 token 唯一且校验通过；E2E：移动端按 token 取回设施信息（不测二维码图片） |
| FR-403 | **报修/巡检工单**：扫码或台账发起工单（设施+问题描述+上报人），按 4 态流转，办结需反馈内容 | 工单依序 accept→dispatch→resolve→approve 成功；非法流转被拒；E2E 覆盖一次完整闭环 |
| FR-404 | **工单留痕与绩效（可选）**：每态记录操作人/时间；绩效积分字段存在但可空（一期不强制启用积分规则） | 工单流转历史完整可查；积分字段为 NULL 时业务不受影响 |
| FR-405 | **设施查询**：按类型/所属村/状态分页查询 | 三种过滤条件返回结果与种子数据一致 |

### 4.5 FR-5xx 墒情/气象/虫情时序与阈值告警（sim 服务，FastAPI 非 GraphQL）

模拟传感器 6 类×每村 2 台（4 村共 48 台）：**土壤墒情、气温、风速、降雨量、虫情指数、水位**（metric 命名以 04 号 DDL 冻结为准，sensor_code CHAR(20)）。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-501 | **模拟设备注册**：种子注册 6 类×2 台/村模拟设备，绑定村与地块 | 设备清单接口返回 48 台（或种子脚本声明的数量），编码符合规则 |
| FR-502 | **时序写入**：`POST /sim/tick` 生成观测值批量写 `hsf_ts.sensor_reading`（1000 条/批，含 sensor_code/metric/value/recorded_at，索引 idx_code_time） | tick 后 `/sim/latest` 返回各设备最新值（05 号 §7.1 冻结路径——评审 R10）；连续 tick 数据量单调递增 |
| FR-503 | **阈值规则引擎（一期 4 条）**：墒情<15% → 旱情告警；墒情>85% → 渍害告警；风速>17m/s → 大风告警；虫情指数>80 → 虫害告警。命中即写 `hsf_biz.alert_record` | 单测：4 条规则边界值（14.9/15.1、84.9/85.1、16.9/17.1、79.9/80.1）触发行为正确；E2E：`/sim/alerts` 返回真实告警 |
| FR-504 | **告警三态生命周期**：待处置 → 处置中 → 已闭环；处置人/时间留痕；接口形态由 05 号文档冻结（最低验收口径：可查询、可统计） | 告警可按状态过滤查询；状态推进留痕（若一期实现仅含查询与统计，以 05 号冻结口径为准并在 20 号报告如实记录） |
| FR-505 | **告警统计**：按类型/村/状态统计数量（`/sim/alerts/statistics`，05 号 §7.1 冻结路径——评审 R10） | 统计值与 alert_record 明细聚合一致 |

### 4.7 FR-7xx 权限与审计（iam 子图，贯穿）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-701 | **组织与账号**：县-乡-村三级组织树+管护主体/合作社两类主体组织；账号=手机号+口令（SM3-PBKDF2 派生），JWT 载荷含 sub/roles/org | ① 组织树查询返回 ≥9 节点（1 县+2 乡+4 村+管护主体+合作社）；② 正确口令签发 token 且 `sub` 为字符串（PyJWT≥2.10 约束，`CONVENTIONS.md` §2.1）；③ 错密返回 401 |
| FR-702 | **RBAC+数据范围**：五角色（admin/town/village/keeper/coop）×数据范围（全县/本乡镇/本村/所辖设施/关联地块）；越权查询返回空集或 403 | ① village 查询地块仅返回本村；② keeper 仅见所辖设施工单；③ 越权写操作 403 且记审计 |
| FR-703 | **网关身份链**：网关校验 JWT 后注入 `x-user-id`/`x-user-roles`/`x-user-name`（Base64）；子图解码头像失败按明文回退；子图不直收外部伪造头（经网关端口访问） | 无 token 访问 401；伪造身份头不生效（E2E 断言）；中文姓名经 Base64 传递正常显示 |
| FR-704 | **审计日志**：全部写操作（创建/流转/处置/登录成功与失败）落审计（who/when/action/object/ip/结果），仅插入不可改；支持按用户/时间/动作过滤 | 执行一次 `createProject` 后审计新增 1 条含 user_id；越权 403 请求亦有审计记录 |
| FR-705 | **限流保护**：网关令牌桶 cap=6000/min（env RATE_CAP 可调），按 user.sub 或 ip 分桶，超限 429 | E2E：高频请求触发 429（对齐 DV-IAS 限流触发用例） |

## 5. 非功能需求（NFR，量化）

| 编号 | 类别 | 指标与目标值 | 验证方法（可执行） | 假设 |
|---|---|---|---|---|
| NFR-01 | 并发容量 | 同时在线 **≥5 万**（容量设计目标）；一期最低实测门槛：k6 browse 200VU + report 20VU **0 失败** | ① 容量模型推演（复用 DV-IAS 已验证基线：同集群 k6 350VU 峰值 20.6 万请求 0 失败、读 p95 355ms，`docs/15`；5~10 万在线模型，`docs/00` §5）；② k6 baseline/stress 实测留档至 20 号报告 | A5 |
| NFR-02 | 读时延 | 核心 GraphQL 查询 **p95 ≤ 500ms**（k6 browse 场景） | k6 baseline.js 实测输出 p95；Prometheus/Grafana 复核 | — |
| NFR-03 | 写时延 | 写操作（mutation 含落库）**p95 ≤ 800ms**（k6 report 场景） | k6 report 场景实测 p95（DV-IAS 同类写路径实测 p95 31ms，余量充足） | — |
| NFR-04 | 时序写入吞吐 | **≥1 万条/秒**：批量 1000 条/批 × ≥10 批/s 持续 ≥60s，0 失败、无死锁/锁冲突错误 | sim 批量写基准压测（脚本与结果入 20 号报告）；对照 DV-IAS 亿行写入吞吐结论（`docs/15` 数据层 1 亿行验证） | A4 |
| NFR-05 | 可用性 | 核心服务可用性 **≥99.9%**（月停机 ≤43.8min）；单实例故障自愈：kill 任一副本 pod 后 ≤60s 恢复服务 | Prometheus 可用率计算（验收窗口内 5xx+探针失败时长占比）；故障注入演练记录 | A6 |
