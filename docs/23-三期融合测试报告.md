**消息级对账（终版+R1 合计，真实计数闭环）**：

```
published（sim tick 响应累计）  2,422,586（R1 1,192,102 + 终版 1,230,484）
− broker 侧丢弃（对账推断）      ≈0.49~0.61M（mosquitto max_queued_messages 10000 对慢消费者丢 QoS1；
                                  下界=未修正心跳贡献，上界=扣除心跳 ~0.12M 修正式）
= iot 实收                      ≈1.81~1.93M
  = written 1,726,707（hsf_iot_readings_written_total，排空后稳定不再增长；含心跳写入）
  + onconflict_skipped 202,210（uk_reading 幂等拦截）
```

**W-1 结论：静态改造已落地并验证（sim/broker 两侧 inflight=1000），但性能预期未兑现**——瓶颈发生转移，证据链：
1. sim 发布器与 broker TCP 连接全程未断（mosquitto 日志 `hsf-sim-pub` 仅 1 次 connect、源端口 37901 连续），排除"连接断开"类解释；
2. sim 每 tick 实际接受发布 ≈6.2k/25.5k 名义（rc≠SUCCESS 占比高，疑似 paho 客户端发送队列满时 `MQTT_ERR_QUEUE_SIZE`——待专项定位，P3-4 列出）；
3. broker 对慢消费者丢 QoS1（对账推断 ~0.5M，见上）；
4. iot 单刷写线程 × 500 行/批 × 0.3-0.5s 批延迟（时序表 2M→17.4M 行后 insert 变慢 + 每批规则评估叠加）构成 ~1,200 条/s 的稳态上限——二期 5,524 条/s 不可复现的量化主因。

**常规链路不受影响**：E2E 用例 15（tick 后 5s 内 latest 可查）静默窗口实测落库 2.1s；R2 的 `published=0` 系与 iot-write 并发所致（静默轮复测 PASS），不构成回归。
