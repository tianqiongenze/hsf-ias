# HSF 高标准农田信息平台 — 建设方案总览与确认清单

> 版本：v1.0 ｜ 编制日期：2026-11-07 ｜ 文档状态：**待确认（C1~C6 默认值已定，见 §8）**
> 编制依据：《数字化、数字智慧农业高标准农田信息平台解决方案架构应如何搭建?》（"五横三纵+用户层"）能力拆解与融合性分析（`docs/18`）、`hsf/CONVENTIONS.md`（工程强制约定）、DV-IAS 项目实战资产（`docs/00~17`、`dv-ias/`）
> 决策结论：**独立立项（不融入 DV-IAS）+ 复用共享底座 + GraphQL Federation 联邦集成**（`docs/18` §3.2）

---

## 1. 项目一句话定位

在现有两台服务器（10.167.2.175 / 10.167.2.176）的 Kubernetes 集群及 TiDB、Prometheus/Grafana、私有镜像仓库等既有基础设施之上，按照 **"独立立项 + 共享底座 + 联邦集成"** 策略，采用 **DDD 五限界上下文（iam/land/project/facility/sim）+ GraphQL Federation（Apollo Gateway + Strawberry 子图）+ TiDB 三库（hsf_md/hsf_biz/hsf_ts）+ 多级缓存 + 等保三级与国密安全栈**，建设面向 **县农业农村局/乡镇/村/管护主体/合作社** 五类角色、支撑 **≥5 万在线**、以 **统一编码、一张图、项目全周期、设施管护、IoT 模拟告警** 为一期范围的高标准农田信息平台。

## 2. 背景与定位口径

- **需求来源**：原文章提出"五横三纵+用户层"的高标准农田信息平台架构（感知/网络/数据/平台/应用五横，标准规范/安全保障/运维运营三纵）。经 `docs/18` 逐能力对照，DV-IAS 仅可直接复用约 30%（治理底座/安全/工单/运维），GIS、项目全周期、IoT 硬件等约 55% 为全新业务域——**因此独立立项，而非融入**。
- **本平台一期（HSF）**：聚焦"农田建设监管"主线（家底摸清→项目管好→设施护好→农情感知），IoT 采用**模拟数据**（sim 服务生成），真实硬件接入、遥感解译、上级平台对接放二期/三期（见 §6）。
- **与 DV-IAS 的关系**：两平台平行运行、互不阻塞；通过 GraphQL Federation `@key` 实体预留互查（如 DV-IAS 农户 ↔ HSF 地块权属），一期不强制打通。

## 4. 与 DV-IAS 的复用边界（共享底座清单）

**复用原则**：底座"移植改名"（不引入运行时依赖），业务"各自建模"（不污染限界上下文）。

### 4.2 明确不复用（边界声明）

| 项 | 理由 |
|---|---|
| DV-IAS 业务子图（portal/gov/points/mcp/agent 等） | 领域不同（乡村治理 vs 农田建设监管），硬塞破坏 DDD 边界（`docs/18` §3.1） |
| `szxc*` 数据库与 `szxc-prod/dev` 命名空间 | 已下线 DROP（`docs/17`），HSF 全新建 hsf_* 资源 |
| Milvus/NebulaGraph/Pulsar/LiteLLM/Ollama | 一期无 RAG/图谱/事件总线/大模型诉求；sim 直接批量写 TiDB，消息队列二期接真实设备时再评估 |
| DV-IAS 的地块/项目/设施主数据 | DV-IAS 无这三类编码体系（`docs/18` §二），HSF 自建 |

### 6.2 与 `docs/18` 一期口径的差异（显式声明）

| docs/18 一期原文 | HSF 一期实际 | 差异理由 |
|---|---|---|
| 时空库(PostGIS)+一张图(OpenLayers/Cesium) | TiDB GeoJSON+纯 SVG/Leaflet 渲染 | 集群无 PostGIS、降低有状态服务；02 号文档 ADR 承载，二期再评估 |

### 6.3 二期/三期展望（不在本次确认范围）

- **二期**：真实 IoT 中台（MQTT/NB-IoT 接入、协议解析、消息队列评估）、气象/墒情/水质/虫情真实感知、智慧生产（灌溉建议，CPU 推理策略）、消息推送。
- **三期**：遥感影像接入与解译、AI 中台模型、耕地质量评价、监管决策（非农化非粮化）、对接全国农田建设综合监测监管平台/国土一张图、数字孪生（可选）。

## 7A. 容量与指标口径（诚实声明）
